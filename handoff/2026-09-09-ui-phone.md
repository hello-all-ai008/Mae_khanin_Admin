## 🚨 1. แจ้งเตือนปัญหาสำคัญเร่งด่วน & การวิเคราะห์สาเหตุเชิงลึก (Urgent Known Issues & Root Cause Analysis)

### 🔴 ปัญหาที่ 1: Check-in แล้วหน้า Monitor ไม่ Realtime และเวลาไม่ตรงกัน

#### 1.1 พฤติกรรมของปัญหาที่พบ:
1. เมื่อเจ้าหน้าที่สแกน BIB นักวิ่งที่หน้า `CheckIn.jsx` ฝั่ง Admin ข้อมูลนักวิ่งบนหน้า `Monitor.jsx` ฝั่ง Runner ไม่เด้งขึ้นมาแสดงผลทันทีแบบ Real-time (ต้องกดรีเฟรชหรือเปิดหน้าจอใหม่)
2. เมื่อข้อมูลแสดงผลบนหน้า Monitor เวลาที่ปรากฏในกล่องสถานะ **"Check in"** กลับไม่ตรงกับเวลาที่เจ้าหน้าที่สแกน Check-in บนหน้า Admin (เช่น สแกนตอน 19:45 น. แต่หน้าจอกลับแสดง 06:00:00 น. หรือเวลาอื่น)

#### 1.2 สาเหตุเชิงเทคนิค (Technical Root Causes):
1. **การเชื่อมต่อหลุดจาก Dependency Loop ใน `Monitor.jsx`:**
   - ใน `Monitor.jsx` มี `useEffect` ที่สร้าง Channel Realtime ฟัง `supabase.channel('rohn_monitor_stream')` โดยใส่ `[castEvent, monitorId, getRunnerByBib]` ไว้ใน Dependency Array
   - เมื่อมี Broadcast เข้ามา `RunnerContext` จะอัปเดต `setCastEvent(...)` ส่งผลให้ `castEvent` เปลี่ยนค่า
   - การเปลี่ยนค่าของ `castEvent` ส่งผลให้ React ทำลาย Subscription เดิม (`supabase.removeChannel(supabaseChannel)`) แล้วสร้างใหม่ทันที ทำให้เกิดช่วงเวลาที่ WebSocket ขาดการเชื่อมต่อ (Connection Churn) ข้อมูลที่ยิงตามมาจึงหลุดและไม่ Realtime
2. **การนำเวลา `gun_start_time` (เวลาปล่อยตัว) มาแสดงแทนเวลา Check-in จริง:**
   - ใน `Monitor.jsx` ฟังก์ชันหาเวลา `effectiveTime` มีลำดับการ fallback ที่ดึง `displayData.gunStartTime` หรือ `runner.gun_start_time` (ซึ่งเป็นเวลาเริ่มงานตอนเช้า เช่น `06:00:00`)
   - ใน `CheckIn.jsx` ตัวแปร `eventPayload` มีการส่ง `gunStartTime: runnerData.gun_start_time || checkinTime`
   - เมื่อนักวิ่งมีข้อมูลเวลาปล่อยตัวในระบบอยู่แล้ว หน้า Monitor จึงนำเวลา 06:00:00 น. ไปแสดงผลแทนที่จะเป็นเวลาที่สแกนเช็คอินจริง (Check-in Timestamp)
3. **การแยก Origin ระหว่างพอร์ต 5173 (Admin) กับ 5174 (Runner):**
   - เบราว์เซอร์แยก `localStorage` และ `BroadcastChannel` ออกจากกันโดยเด็ดขาด การส่งสัญญาณจึงต้องพึ่งพา Supabase Realtime Broadcast 100% ซึ่งต้องการการเชื่อมต่อที่เสถียรและคงอยู่ตลอดเวลา (Persistent Channel)

#### 1.3 แนวทางแก้ไขที่ต้องดำเนินการ (Action Plan):
- แยก `useEffect` สำหรับเชื่อมต่อ Supabase Realtime ใน `Monitor.jsx` ออกมาต่างหาก โดยผูกกับ `[monitorId]` เท่านั้น ไม่นำ `castEvent` มาร่วมเป็น Dependency เพื่อป้องกันการ Re-subscribe ซ้ำซ้อน
- ปรับลำดับการแสดงผลเวลาใน `Monitor.jsx` ให้ยึด `displayData.checkinTime` เป็นอันดับ 1 เสมอ หากไม่มีจึงค่อยแสดงเวลาปัจจุบันหรือ `--:--:--`
- ส่งเวลา Check-in ที่แน่นอนในรูปแบบ ISO String และ Timestamp ชัดเจนจาก `CheckIn.jsx`

### 🔴 ปัญหาที่ 2: หน้าแก้ไขเวลา ลบเวลาออกไปแล้ว แต่กลับมา Check-in ใหม่ไม่ได้

#### 2.1 พฤติกรรมของปัญหาที่พบ:
- เมื่อผู้ดูแลระบบเข้าไปที่หน้าจัดการเวลา (`RunnerTimingModal` หรือ `RunnerProgressControl`) แล้วทำการลบเวลา Check-in ออก (เช่น ลบเวลาออกเพื่อทดสอบระบบใหม่ หรือเปลี่ยนสถานะกลับเป็น `PRE_REGISTERED`)
- เมื่อกลับมาที่หน้า `CheckIn.jsx` แล้วสแกน BIB เดิมซ้ำ ระบบกลับแจ้งเตือนว่า **"Check in แล้ว : XX:XX:XX (ยึดเวลาแรก)"** และไม่ยอมให้สแกนบันทึกเวลาใหม่

#### 2.2 สาเหตุเชิงเทคนิค (Technical Root Causes):
1. **ความไม่สอดคล้องกันของตัวแปรในระบบ (`checked_in_at` vs `r.checkin`):**
   - ฐานข้อมูลจริงใน Supabase ใช้คอลัมน์ชื่อ `checked_in_at` (TIMESTAMP) และ `registration_status`
   - แต่ในส่วนของ In-Memory State ของ `RaceContext.jsx` มีการสร้างตัวแปรชั่วคราวชื่อ `r.checkin` เก็บตัวเลขอีพ็อก (Epoch Milliseconds) ไว้ใช้งานภายใน
2. **การลบเวลาใน Modal อัปเดตเฉพาะ Supabase แต่ไม่เคลียร์ State ใน `RaceContext`:**
   - เมื่อกดบันทึกใน `RunnerTimingModal.jsx` ระบบส่งคำสั่งอัปเดตไปยัง Supabase:
     ```javascript
     registration_status: 'PRE_REGISTERED',
     checked_in_at: null
     ```
   - แต่ในฝั่ง `RaceContext` ตัวแปร `runners` ในหน่วยความจำและในแคช `localStorage` (`trail_cached_runners_...`) ยังคงมีค่า `r.checkin = 17258...` ค้างอยู่ ไม่ได้ถูกเซ็ตเป็น `null`
3. **เงื่อนไขในฟังก์ชัน `processScan` ตรวจจับเฉพาะ `if (r.checkin)`:**
   - ใน `RaceContext.jsx` บรรทัดที่ 1063:
     ```javascript
     if (r.checkin) {
       result.success = false;
       result.isRescan = true;
       result.message = `Check in แล้ว : ${firstTimeStr} (ยึดเวลาแรก)`;
       return result;
     }
     ```
   - เมื่อ `r.checkin` ในหน่วยความจำยังมีค่าอยู่ แม้ในฐานข้อมูล `checked_in_at` จะเป็น `null` ไปแล้ว ระบบจึงมองว่าเป็น **สแกนซ้ำ (Rescan)** ทันที และปฏิเสธการเช็คอินใหม่

#### 2.3 แนวทางแก้ไขที่ต้องดำเนินการ (Action Plan):
- ใน `RunnerTimingModal.jsx` เมื่อมีการลบเวลาเช็คอินออก ต้องอัปเดตให้ `checkin: null` ควบคู่กับ `checked_in_at: null` เสมอ
- เพิ่มฟังก์ชันซิงค์ใน `RaceContext.jsx` ให้ทำการรีเฟรชข้อมูลนักวิ่ง (`refreshRunners()`) หรืออัปเดต `updateRunner(...)` ให้ `r.checkin = null` ทันทีเมื่อมีการแก้ไขเวลา
- ปรับเงื่อนไขใน `processScan` ให้ตรวจสอบควบคู่กันระหว่าง `r.registration_status === 'CHECKED_IN'` และ `r.checked_in_at` หากใน Database ถูกล้างเป็น null แล้ว ต้องอนุญาตให้เช็คอินใหม่ได้ทันที

## 📱 2. สรุปงานที่ทำในวันนี้ (Work Completed Today — 2026-09-09)

### 2.1 ปรับแต่ง Mobile UI หน้าสแกนให้พอดีกับโทรศัพท์ทุกรุ่น (Responsive Scanner Pages)
* **ไฟล์ที่แก้ไข:**
  - `Rohn-Admin/src/pages/CheckIn.jsx`
  - `Rohn-Admin/src/pages/CheckPoint.jsx`
  - `Rohn-Admin/src/pages/FinishLine.jsx`
* **รายละเอียดการปรับปรุง:**
  1. **ขจัดปัญหาจอล้นแนวนอน (No Horizontal Overflow):** กำหนด `width: 100%`, `max-width: 100%`, `box-sizing: border-box`, และ `overflow-x: hidden` ให้กับคอมโพเนนต์หลักทั้งหมด
  2. **Responsive Live Statistics Card:** ปรับแถบสรุปยอดสแกนด้านบนให้อยู่ในรูปแบบ `.stat-grid-3` (`grid-template-columns: repeat(3, minmax(0, 1fr))`) ใช้ฟอนต์ขนาด `clamp()` ทำให้อ่านง่ายบนจอมือถือขนาดเล็ก (เช่น iPhone SE, iPhone 13 mini) โดยไม่เกิดการตกบรรทัดหรือล้นขอบจอ
  3. **Table Optimization:** ตารางประวัติการสแกนปรับให้รองรับการปัดเลื่อนเฉพาะตัวตาราง (`overflow-x: auto`) เพื่อให้โครงสร้างหน้าจอหลักไม่ขยับเขยื้อน

### 2.2 ออกแบบ Dark LED Runner Details Card สำหรับหน้าจอมือถือ (`MobileScanResultCard.jsx`)
* **ไฟล์ที่สร้าง:** `Rohn-Admin/src/components/MobileScanResultCard.jsx`
* **ฟีเจอร์เด่น:**
  - ยกรูปแบบกระดาน LED ขนาดใหญ่จากหน้าจอคอมพิวเตอร์ (PC) มาย่อส่วนให้อยู่ในหน้าจอมือถือได้อย่างสวยงาม
  - **BIB Badge ขนาดใหญ่พิเศษ:** แสดงหมายเลข BIB ชัดเจน สังเกตเห็นได้ทันทีแม้ใช้งานกลางแจ้ง
  - **Runner Info:** แสดงชื่อนักวิ่ง, สัญชาติ/ธงชาติ, รุ่นอายุ, ระยะทางวิ่ง
  - **Category Badge พร้อมสีประจำระยะ:** แสดง Tag สีตามระยะทางจริง (เช่น 10KM สีฟ้า, 5KM สีเขียว)
  - **Scan Status & Message:** แสดงสถานะผ่าน (สีเขียว), สแกนซ้ำ (สีส้มเตือน), หรือไม่พบในระบบ (สีแดง) พร้อมเวลาสแกนจริง

### 2.3 ลดความรกรุงรังของหน้าจอ (Streamlined & Clean Scanner UI)
* **แยกการตั้งค่าสถานี (Station Setup):** ย้ายการเลือกจอ Monitor, การสลับผู้สแกน (Staff/Operator), และเมนูจัดการแคชออฟไลน์ ไปรวมอยู่ในปุ่ม **"ตั้งค่า" (StationSetupModal)** เปิดแบบ Pop-up Modal เมื่อต้องการใช้งานเท่านั้น
* **พับเก็บประวัติการสแกนได้ (Collapsible Scan History):** เพิ่มปุ่มสลับเปิด/ปิด **"ประวัติการสแกน (XX)"** ทำให้บนหน้าจอมือถือมีพื้นที่โฟกัสที่ช่องสแกนกล้องและการ์ดผลลัพธ์นักวิ่งได้อย่างเต็มที่

### 2.4 ปรับปรุงหน้าจอ Monitor ฝั่ง Runner (`Monitor.jsx`)
* **ไฟล์ที่แก้ไข:** `Rohn-Runner/src/pages/Monitor.jsx` & `RunnerContext.jsx`
* **รายละเอียด:**
  1. **เปลี่ยนป้าย "START DATE" เป็น "Check in":** ปรับเปลี่ยนข้อความสถานะบนจอ Monitor ตามที่ผู้ใช้ระบุ จากเดิมที่แสดงคำว่า `START DATE` เปลี่ยนเป็นคำว่า **`Check in`**
