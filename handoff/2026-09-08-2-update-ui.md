## 2. Leaderboard UI & English Text Normalization

### 2.1 The Issue
- Previously, age group ranking cards occupied the full width of mobile screens (`1fr`), with oversized typography (`1.3rem` headers, large ranks, generous padding). On mobile phones, users could only view 1 table at a time, requiring extensive vertical scrolling.
- Database records for categories, age groups, and genders often contain bilingual strings like `"40-49 ปี (40-49 years)"` or `"ชาย (Male)"`. The user requested showing strictly the English text within the parentheses.

### 2.2 Solutions Implemented

#### A. English Parentheses Extraction (`formatEnglishLabel`)
Enhanced `formatEnglishLabel(val)` in both `Rohn-Runner/src/components/ESlip.jsx` and `Rohn-Admin/src/components/ESlip.jsx`:
- **Regex Extraction:** Matches `/\(([^)]+)\)/` to extract text inside parentheses (e.g. `"40-49 ปี (40-49 years)"` ➔ `"40-49 years"`).
- **Gender Extraction:** `"ชาย (Male)"` ➔ `"Male"`, `"หญิง (Female)"` ➔ `"Female"`.
- **Thai Fallbacks:** If parentheses are absent, patterns such as `"40-49 ปี"` convert to `"40-49 yrs"`, `"ไม่เกิน 29 ปี"` convert to `"Under 29 yrs"`, `"60 ปีขึ้นไป"` convert to `"60 yrs & over"`, and `"ชาย"` / `"หญิง"` convert to `"Male"` / `"Female"`.
- **Applied to:**
  - Overall Champions Cards: Male/Female badges display `"Male"` and `"Female"` instead of `"ชาย"` / `"หญิง"`; runner age group displays `· 40-49 years` without `"รุ่น"`.
  - Group Header: `${cleanAge} (${cleanGender})` (e.g. `10KM | 40-49 years (Male)`).

#### B. High-Density Multi-Table Grid Layout
- **Mobile Phones (`<= 768px`):**
  - Grid configuration: `grid-template-columns: repeat(2, minmax(0, 1fr)) !important;` with `0.45rem` / `6px` gap.
  - Card padding reduced to `0.45rem - 0.5rem` (`7px 6px`).
  - Rank badge scaled to `14px - 16px` with compact circular/square container.
  - Runner name scaled to `0.68rem - 0.72rem` with ellipsis truncation (`max-width: 65px - 80px`).
  - Row padding reduced to `0.15rem`, minimizing card height to `~135px - 145px`.
  - Result: Users on standard mobile displays (height ~800px) can comfortably inspect **4 to 6 tables simultaneously**.
- **Desktop & Tablets:**
  - Grid configuration: `grid-template-columns: repeat(auto-fill, minmax(260px, 1fr));` with `1rem` / `12px - 14px` gap.
  - Accommodates **4 to 5 tables per row** across standard 1080p and 1440p displays.

### 6.2 Detailed Gap Analysis by Component

#### A. `RunnerPageConfig.jsx` — The `RUNNER_CONFIG` Workaround
- **Current Implementation:**
  ```javascript
  // RunnerPageConfig.jsx (Line 120-126)
  const { data } = await supabase
    .from('runners')
    .select('id, cps')
    .eq('event_id', selectedEventId)
    .eq('bib', 'RUNNER_CONFIG')
    .maybeSingle();
  ```
- **The Problem:** Storing application UI toggles inside the `runners` table using a fake runner with `bib = 'RUNNER_CONFIG'` is an anti-pattern. Any backend calculation (e.g., total registered count, BIB generation, chip lookup) that does not explicitly filter out `'RUNNER_CONFIG'` will count this configuration dummy as a registered athlete.
- **Proper Architecture according to `DatabaseFlow.jsx`:**
  - Option 1 (Recommended): Add a `config` `JSONB` column to the `events` table:
    ```sql
    ALTER TABLE public.events ADD COLUMN IF NOT EXISTS config JSONB DEFAULT '{}'::jsonb;
    ```
  - Option 2: Use an `app_settings` key-value table:
    ```sql
    CREATE TABLE IF NOT EXISTS public.app_settings (
        id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
        event_id UUID REFERENCES public.events(id) ON DELETE CASCADE,
        key VARCHAR(100) NOT NULL,
        value JSONB NOT NULL,
        updated_at TIMESTAMPTZ DEFAULT now(),
        UNIQUE(event_id, key)
    );
    ```

#### B. `RunnerProgressControl.jsx` — Disconnect from `SCAN_LOGS` and `ACTION_LOGS`
- **Current Implementation:**
  When an admin clicks "Quick Reset" or "Bulk Reset", the tool updates `runners`:
  ```javascript
  await supabase.from('runners').update({
    registration_status: 'PRE_REGISTERED',
    checked_in_at: null,
    checked_in_by: null,
    cps: {},
    finish: null
  }).eq('id', runner.id);
  ```
- **The Problem:**
  1. The `SCAN_LOGS` table (defined in Section 2.8 of `DatabaseFlow.jsx`) holds the raw scan history. Clearing `runners.cps` without deleting or archiving matching `SCAN_LOGS` rows results in data inconsistency: `SCAN_LOGS` claims scans occurred, but the runner's record shows they never ran.
  2. Destructive actions (bulk resets, manual DNS/DNF overrides) are performed without inserting an entry into `ACTION_LOGS` (`id, admin_id, action_type, created_at`).
  3. No Admin PIN prompt (defined in `ADMIN_USERS.pin`) is required prior to wiping dry-run data.
- **Proper Architecture:**
  - During single or bulk reset:
    1. Verify PIN against `ADMIN_USERS.pin`.
    2. Write an audit log to `ACTION_LOGS` (`action_type = 'RESET_RUNNER_DATA'`, `admin_id = currentAdminId`).
    3. Either `DELETE FROM scan_logs WHERE runner_id = ...` or update `scan_logs SET is_valid = false WHERE runner_id = ...`.

#### C. `LiveLeaderboard.jsx` — Missing `CHECKPOINT` Route Adherence
- **Current Implementation:**
  `LiveLeaderboard.jsx` ranks runners primarily by comparing `finishEpoch - startEpoch`.
- **The Problem:**
  `DatabaseFlow.jsx` defines a specific relational model:
  `CATEGORIES ||--o{ CHECKPOINT : "defines_route"`  
  `STATIONS ||--o{ CHECKPOINT : "used_in"`  
  Each category has an ordered route of required checkpoints (e.g., Start ➔ A1 ➔ A2 ➔ Finish). If a 10KM runner misses checkpoint A1 or A2, they should be flagged as "Missed Checkpoint" or disqualified (DQ) rather than automatically awarded 1st place in their age group simply because their finish gun time was fastest.
- **Proper Architecture:**
  Query the `checkpoint` table joined with `stations` for `runner.category_id`. Verify that `Object.keys(runner.cps)` contains every required `checkpoint.station_id` before admitting the runner into official leaderboard medal rankings.

### 6.3 Actionable Migration Plan & Remediation SQL

To bring the new features into full compliance with `DatabaseFlow.jsx`, execute the following SQL in the Supabase SQL Editor:

```sql
-- 1. Add config JSONB column to events table to replace the RUNNER_CONFIG hack
ALTER TABLE public.events 
ADD COLUMN IF NOT EXISTS config JSONB DEFAULT '{
  "scanner": true,
  "monitor": true,
  "eslip": true,
  "dashboard": true,
  "leaderboard": true,
  "displayMode": "disabled_badge",
  "notices": {}
}'::jsonb;

-- 2. Migrate existing RUNNER_CONFIG data from runners into events.config
UPDATE public.events e
SET config = r.cps
FROM public.runners r
WHERE r.event_id = e.id 
  AND r.bib = 'RUNNER_CONFIG'
  AND r.cps IS NOT NULL 
  AND r.cps != '{}'::jsonb;

-- 3. Clean up the dummy RUNNER_CONFIG rows from runners table
DELETE FROM public.runners WHERE bib = 'RUNNER_CONFIG';

-- 4. Ensure ACTION_LOGS and ADMIN_USERS tables exist per DatabaseFlow.jsx
CREATE TABLE IF NOT EXISTS public.admin_users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255) NOT NULL,
    pin VARCHAR(10) NOT NULL,
    created_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE IF NOT EXISTS public.action_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    admin_id UUID REFERENCES public.admin_users(id) ON DELETE SET NULL,
    action_type VARCHAR(100) NOT NULL,
    event_id UUID REFERENCES public.events(id) ON DELETE CASCADE,
    details JSONB DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ DEFAULT now()
);
```
