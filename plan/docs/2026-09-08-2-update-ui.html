1 ปรับปรุงตารางผลการแข่งขัน (Live Leaderboard) และการแสดงผลภาษาอังกฤษ

เดิมทีทั้งใน Rohn-Admin (LiveLeaderboard.jsx) และ Rohn-Runner (Leaderboard.jsx) เมื่อเปิดดูบนโทรศัพท์มือถือ ตารางแต่ละรุ่นจะกินพื้นที่แนวตั้งเต็มความกว้าง (1 คอลัมน์) ขนาดตัวหนังสือและ Padding ใหญ่ ทำให้ต้องเลื่อนจอนานมากเพื่อดูผลรุ่นต่างๆ นอกจากนี้ ชื่อรุ่นและเพศที่ดึงมาจากฐานข้อมูลจะมีข้อความภาษาไทยปนภาษาอังกฤษ เช่น 40-49 ปี (40-49 years) หรือ ชาย (Male)

🔤 แสดงเฉพาะภาษาอังกฤษในวงเล็บ

สร้างและขยายความสามารถฟังก์ชัน formatEnglishLabel(val) ให้รองรับทุกกรณี:

  • ดึงเฉพาะข้อความภาษาอังกฤษในวงเล็บ (...) มาแสดง เช่น 40-49 ปี (40-49 years) ➔ 40-49 years
  • แปลงเพศเป็นภาษาอังกฤษสากล ชาย (Male) ➔ Male, หญิง (Female) ➔ Female
  • ป้ายทำเนียบ Overall เปลี่ยนจาก ชาย/หญิง เป็น Male/Female และตัดคำนำหน้าภาษาไทย "รุ่น" ออก
  • หัวข้อตารางแสดงเป็นภาษาอังกฤษล้วน เช่น 10KM | 40-49 years (Male)
  • มีระบบ Fallback อัจฉริยะรองรับกรณีข้อมูลใน DB มีแค่ภาษาไทยล้วน

📱 UI โทรศัพท์แบบหลายตาราง (Multi-Table Grid)

จัดวางเลย์เอาต์ใหม่ให้เห็นหลายตารางพร้อมกันโดยไม่ต้องเลื่อนหน้าจอเยอะ:

  • มือถือ (≤ 768px): ปรับ Grid เป็น 2 คอลัมน์คู่ขนาน (repeat(2, minmax(0, 1fr)))
  • ลด Padding ตารางเหลือเพียง 6px-8px และลดความสูงแถวนักวิ่ง
  • ย่อขนาดตัวอักษรลงเป็น 0.68rem - 0.72rem พร้อม Truncate ป้องกันชื่อยาวล้น
  • ความสูงของแต่ละตารางเหลือเพียง ~135px - 145px ทำให้หน้าจอมือถือมาตรฐานสามารถมองเห็นได้ทีละ 4-6 ตารางพร้อมกัน
  • Desktop/Tablet: แสดงผล 4-5 ตารางต่อแถวอย่างสวยงามและสมดุล

2 หน้าใหม่ใน Rohn-Admin: จัดการสถานะนักวิ่ง / รีเซ็ตเวลา (RunnerProgressControl)

เพิ่มหน้าใหม่ภายใต้เมนู "จัดการข้อมูล" ในโปรเจกต์ Rohn-Admin (ที่ Route /runner-progress-control) เพื่อให้อาจารย์และผู้จัดสามารถควบคุม ตรวจสอบ และทดสอบระบบก่อนการแข่งขันจริง:

ความสามารถหลัก รายละเอียดการทำงาน
ตรวจสอบเส้นทางและจุดสแกน แสดงผัง Checkpoint ของนักวิ่งแต่ละคนตามระยะทาง/รุ่นที่ลงทะเบียน (อ้างอิง Flow จาก DatabaseFlow.jsx) ตรวจสอบได้ว่าใครต้องผ่านสถานีไหนบ้าง
จัดการสถานะ DNS และ DNF มีปุ่มคลิกกำหนดสถานะ DNS (ไม่มาแข่งขัน) หรือ DNF (วิ่งไม่จบการแข่งขัน) ได้แบบรายบุคคลอย่างรวดเร็ว
แก้ไขและรีเซ็ตเวลา (Timing Override) มีหน้าต่าง Modal ตรวจสอบ/แก้ไขเวลา Check-in, Start Gun, CP แต่ละจุด และ Finish Time รายบุคคล
ระบบรีเซ็ตเพื่อการทดสอบ (Test Reset) มีปุ่ม Bulk Reset สถานะและเวลาการสแกนทั้งหมดของงานเพื่อเริ่มทดสอบรอบใหม่ (Dry-Run Test) พร้อมระบบยืนยันความปลอดภัยเพื่อป้องกันการกดพลาด

⚠️ 1. จุดที่ต้องปรับปรุงด่วน: RunnerPageConfig

ปัจจุบันหน้า RunnerPageConfig.jsx ฝากการตั้งค่าไว้ในตาราง runners โดยสร้าง BIB หลอกขึ้นมาชื่อ RUNNER_CONFIG: 

// โค้ดปัจจุบันที่ใช้ชั่วคราว
const { data } = await supabase
  .from('runners')
  .select('id, cps')
  .eq('bib', 'RUNNER_CONFIG')
  .maybeSingle();

ผลกระทบ: หากวันจริงแอดมินทำการ Import นักวิ่ง หรือ Rebuild BIB ระบบอาจเผลอนำ RUNNER_CONFIG ไปนับเป็นนักวิ่งตัวจริง หรือถูกลบทิ้งเมื่อมีการเคลียร์ข้อมูลนักวิ่ง
แนวทางแก้ไขที่ถูกต้อง: ควรเพิ่มคอลัมน์ config JSONB เข้าไปในตาราง events ตามโครงสร้าง Schema ที่ถูกต้อง

🛡️ 2. จุดที่ต้องปรับปรุง: ความสมบูรณ์ของระบบ Reset ข้อมูล

ในหน้า RunnerProgressControl.jsx เมื่อกด Quick Reset หรือ Bulk Reset:

  • คำสั่งปัจจุบันรันแค่ UPDATE runners SET cps = '{}', finish = null
  • แต่ในตาราง scan_logs ยังมีบันทึกประวัติการสแกนเวลาเก่าค้างอยู่
  • ควรอัปเดตให้คำสั่ง Reset ทำการล้าง scan_logs ของนักวิ่งคนนั้นออกด้วย หรือตั้งค่า is_valid = false
  • ควรเพิ่มการบันทึกลงตาราง action_logs ทุกครั้งที่มีการ Reset ข้อมูล เพื่อป้องกันข้อผิดพลาดและใช้ตรวจสอบย้อนหลังได้

💻 สคริปต์ SQL แนะนำสำหรับปรับปรุงฐานข้อมูลให้ตรงตาม DatabaseFlow

สามารถนำคำสั่ง SQL ด้านล่างนี้ไปรันใน Supabase SQL Editor เพื่อแก้ปัญหาจุดเชื่อมต่อที่ยังค้างอยู่ได้ทันที: 

-- 1. เพิ่มคอลัมน์ config ลงในตาราง events เพื่อใช้เก็บการตั้งค่าหน้า Runner แทนการใช้ BIB หลอก
ALTER TABLE public.events 
ADD COLUMN IF NOT EXISTS config JSONB DEFAULT '{
  "scanner": true,
  "monitor": true,
  "eslip": true,
  "dashboard": true,
  "leaderboard": true,
  "displayMode": "disabled_badge",
  "notices": {}
}'::jsonb;

-- 2. ย้ายข้อมูลการตั้งค่าเดิมจากแถว RUNNER_CONFIG เข้าไปไว้ใน events.config
UPDATE public.events e
SET config = r.cps
FROM public.runners r
WHERE r.event_id = e.id 
  AND r.bib = 'RUNNER_CONFIG'
  AND r.cps IS NOT NULL;

-- 3. ลบแถว BIB หลอก RUNNER_CONFIG ออกจากตาราง runners เพื่อให้ตารางนักวิ่งสะอาด 100%
DELETE FROM public.runners WHERE bib = 'RUNNER_CONFIG';

-- 4. สร้างตาราง staff และ action_logs หากยังไม่มีในระบบ (อิงตาม DatabaseFlow.jsx)
CREATE TABLE IF NOT EXISTS public.staff (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    event_id UUID REFERENCES public.events(id) ON DELETE CASCADE,
    name VARCHAR(255) NOT NULL,
    role VARCHAR(50) DEFAULT 'MARSHAL',
    status VARCHAR(20) DEFAULT 'ACTIVE',
    created_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE IF NOT EXISTS public.action_logs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    admin_id UUID REFERENCES public.admin_users(id) ON DELETE SET NULL,
    action_type VARCHAR(100) NOT NULL,
    event_id UUID REFERENCES public.events(id) ON DELETE CASCADE,
    details JSONB DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ DEFAULT now()
);
