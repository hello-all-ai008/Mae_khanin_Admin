1 ฟังก์ชันที่พัฒนาเสร็จแล้ว (Implemented Features)

🏁 1.1 จุด Check-in (Start)
  • เลือกงานวิ่ง (Event Selector)
  • ค้นหา BIB และตรวจสอบสิทธิ์เช็คอิน
  • ป้องกันการเช็คอินซ้ำ
  • บันทึกเวลาปล่อยตัว และผู้เช็คอิน
  • แสดงผลขึ้นกระดาน LED จำลองทันที
🏔️ 1.2 จุด Check Point (CP)
  • เลือกจุด CP ที่ประจำอยู่ (A1, A2, A3...)
  • ตรวจสอบว่าผ่าน Check-in แล้วหรือไม่
  • ป้องกันการสแกนซ้ำที่จุดเดิม
  • บันทึกเวลาผ่านจุดลงใน cps
  • แสดงประวัติการสแกนแยกตามจุด CP
🏆 1.3 จุด Finish Line (เส้นชัย)
  • ยิงบาร์โค้ดเข้าเส้นชัย
  • คำนวณ Total Time (Gun/Net Time)
  • ป้องกันการทับเวลา (ยึดเวลาแรกเสมอ)
  • บันทึกเวลาเข้าเส้นชัย finish
  • แสดงเวลาสุทธิบนกระดาน LED
⚡ 1.4 สถาปัตยกรรมสแกนแบบลื่นไหล (0ms Decoupled Architecture)
  • สแกนเร็ว 0ms ไม่สะดุด: แยกการประมวลผลการสแกนและตรวจสอบข้อมูลในเครื่องออกจาก Database ทำให้ยิงบาร์โค้ดได้รวดเร็วต่อเนื่องโดยไม่ต้องรอเน็ตตอบกลับ
  • Background Sync Queue: ข้อมูลที่สแกนผ่านจะถูกบรรจุเข้าคิวในเครื่อง (localStorage) ทันที และมี Worker ส่งขึ้น Supabase ในพื้นหลังอัตโนมัติ
  • Offline Resilience: สแกนในจุดอับสัญญาณเน็ตได้ 100% เมื่อต่อเน็ตได้ระบบจะ Auto-Sync ข้อมูลที่ค้างส่งให้อัตโนมัติ
  • Scanner Control: รองรับเครื่องยิง Barcode และกล้องมือถือ (Html5Qrcode) ซูมเลนส์ได้ 1x-3.5x, เปิดไฟแฟลชได้ และมีเสียง Beep Feedback

2 สถานะการเชื่อมต่อ Database (เทียบกับ DatabaseFlow.jsx)

ตารางใน ERD สถานะ คำสั่ง / การทำงานในระบบ รายละเอียด
EVENTS ✓ เชื่อมต่อแล้ว supabase.from('events').select('id, name') ดึงรายชื่องานวิ่งมาใส่ใน Dropdown เลือกงานทั้ง 3 หน้า
CATEGORIES ✓ เชื่อมต่อแล้ว supabase.from('categories').select('*') ดึงระยะทางและเวลาปล่อยตัวในระบบ Preload Cache
STATIONS ✓ เชื่อมต่อแล้ว supabase.from('stations').select('id, name, type') ดึงรายชื่อจุดสแกนมาแสดงในเมนูเลือกจุด CP
CHECKPOINT ✓ เชื่อมต่อแล้ว supabase.from('checkpoint').select(...) ดึงข้อมูลเส้นทางและเวลา Cutoff เพื่อตั้งค่าเวลาเริ่มต้น
STAFF ✓ เชื่อมต่อแล้ว supabase.from('staff').select() / insert() เลือกชื่อเจ้าหน้าที่ผู้สแกน และเพิ่มชื่อใหม่เข้าระบบ
RUNNERS (Read) ✓ เชื่อมต่อแล้ว supabase.from('runners').select('*') โหลดข้อมูลนักวิ่งทั้งงานมาเก็บใน Local Cache พร้อมสแกน
RUNNERS (Check-in) ✓ เชื่อมต่อแล้ว update({ registration_status: 'CHECKED_IN', checked_in_at, checked_in_by }) อัปเดตสถานะเช็คอินผ่าน Background Queue
RUNNERS (CP) ✓ เชื่อมต่อแล้ว update({ cps: updated.cps }) อัปเดต JSONB เวลาผ่าน CP ผ่าน Background Queue
RUNNERS (Finish) ✓ เชื่อมต่อแล้ว update({ finish: timestamp }) อัปเดตเวลาเข้าเส้นชัยผ่าน Background Queue
SCAN_LOGS ⚠ บางส่วน insert([{ runner_id, station_id, scan_time, is_valid: true }]) ส่งเฉพาะรายการที่ผ่าน ยังไม่ได้ส่งรายการที่ไม่ผ่าน (Invalid/ซ้ำ)
LOCATIONS ✗ ยังไม่เชื่อม — ยังไม่ได้นำ location_id มาผูกกับจุดสแกน

3 สิ่งที่ยังขาด และข้อเสนอแนะในการพัฒนาต่อ (Next Steps)

1. การบันทึกประวัติการสแกนแบบสมบูรณ์ (Audit Logs):
ควรขยายให้ตาราง SCAN_LOGS บันทึกทั้งกรณีสแกนสำเร็จและสแกนผิดพลาด (เช่น "BIB ไม่ถูกต้อง", "ยังไม่เช็คอิน", "สแกนซ้ำ") โดยกำหนด is_valid: false เพื่อให้ผู้จัดงานตรวจสอบย้อนหลังได้หากมีข้อพิพาท
2. การตรวจสอบ Cutoff Time (DNF Notification):
หน้า CheckPoint และ FinishLine สามารถนำฟิลด์ cutoff_time จากตาราง CHECKPOINT มาคำนวณและแจ้งเตือนบนหน้าจอทันทีว่านักวิ่ง "เกินเวลา Cutoff (DNF)" หรือไม่
3. การเปิดใช้งาน Supabase Realtime Channel:
เพิ่มการเปิดรับสัญญาณ Realtime เพื่อให้เมื่อเจ้าหน้าที่จุด CP ยิงบาร์โค้ด ข้อมูลจะวิ่งมาอัปเดตบนหน้าจอ Admin หรือ Finish Line ได้ทันทีโดยไม่ต้องกดรีเฟรช
