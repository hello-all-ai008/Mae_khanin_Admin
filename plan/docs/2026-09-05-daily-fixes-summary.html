1 ล็อกจุด Check Point ตาม Station ที่ล็อกอิน

ปัญหาที่ Gong แจ้ง: ทดสอบเข้า station A1 (Loha Prasat) แล้วปุ่ม dropdown เลือกจุด Check Point ยังให้เลือกจุดอื่นได้อยู่ (Start / A1 / A2 / Finish) — เสี่ยงสแกนผิดจุดโดยไม่ตั้งใจ

วิธีแก้: อ่าน station_id ที่ผูกกับบัญชี staff คนนั้นจาก session แล้วล็อก dropdown ให้เหลือแค่จุดที่ได้รับมอบหมาย — บัญชีที่ไม่มี station ประจำ (เช่น Admin ที่คุมได้ทุกจุด) ยังเลือกได้อิสระเหมือนเดิม

2 Leaderboard + Overall Dashboard อัปเดตสด (Realtime)

คำขอ: ให้หน้า Leaderboard และ Dashboard ไม่ต้อง refresh เองทุกครั้งที่มีนักวิ่งถึง Finish หรือผ่านจุด CP

วิธีแก้: เปิด Supabase Realtime บนตาราง runners (migration ใหม่) แล้วให้ทั้ง 2 หน้าฟังการเปลี่ยนแปลง (INSERT/UPDATE) ของ event ที่กำลังดูอยู่ — พอมีสแกนจากเครื่องไหนก็ตาม หน้าจะ fetch ข้อมูลใหม่แบบเงียบๆ ให้เอง (หน่วง 400ms กันสแกนรัว)

ปัญหาที่เจอวิธีแก้
ปุ่ม Refresh ส่ง event object แทนค่า silent → spinner ไม่ขึ้นแก้ปุ่มให้เรียก fetchData() เปล่าๆ
Dashboard กลืน error เงียบ แล้วโชว์ข้อมูลปลอมแทนเพิ่ม throw error ให้ตรงกับ Leaderboard
ฟัง DELETE ทั้งที่ตารางไม่รองรับ (เสี่ยงพลาดแถวลบ)ฟังเฉพาะ INSERT/UPDATE ตรงกับพฤติกรรมสแกนจริง
fetchData สร้างใหม่ทุก render → subscribe ซ้ำ/ค่าเก่าค้างห่อด้วย useCallback + ref สำหรับ state ที่ไม่ควรกระตุ้น re-subscribe

3 แก้บั๊กหน้า Runners แสดงข้อมูลไม่ครบ (ตัดที่ 1,000)

ปัญหา: หน้า "รายชื่อนักวิ่ง" ขึ้น "1,000 records" ทั้งที่ import จริง 1,061 คน — สาเหตุ Supabase/PostgREST จำกัดผลลัพธ์ต่อ 1 คำขอไว้ที่ 1,000 แถวเป็นค่าเริ่มต้น

วิธีแก้: เขียนฟังก์ชันช่วย fetchAllRows() วนดึงทีละ 1,000 แถวจนครบ พร้อม sort แบบตายตัว (order('id')) กันข้อมูลซ้ำ/หายระหว่างแบ่งหน้า และใส่เพดานกันวนลูปไม่รู้จบ — มี unit test ครบ 6 เคส

ผลหลังแก้หน้า Runners แสดงครบ 1,061 รายชื่อจริง ปุ่ม "ล้างรายชื่อทั้งหมด" นับเลขถูกต้องตามจริงด้วย

4 ข้อมูลทดสอบสำหรับซ้อมก่อนงานจริง

เพิ่มข้อมูลจำลอง (checked-in / ผ่าน CP / เข้าเส้นชัย) ให้ BIB จริง 3 เบอร์ (1011, 1012, 5011) เพื่อให้ Gong เห็นชื่อนักวิ่งจริงตอนซ้อมระบบวันที่ 6 ก.ย. — รีเซ็ตกลับสถานะเดิมแล้ว (PRE_REGISTERED, ไม่มีเวลาสแกนค้าง) พร้อมสำหรับงานจริง 12–13 ก.ย.

5 หน้า Admin/Users ใช้งานไม่ได้ทั้งหน้า — ไล่แก้ 4 รอบ

Gong แจ้งว่าโหลดข้อมูลไม่ได้ ไล่ตรวจแล้วพบว่าเป็นบั๊กสะสม 4 ชั้นซ้อนกัน แก้ทีละชั้นจนหน้าใช้งานได้ครบ (ดูรายชื่อ / เพิ่มผู้ใช้ / แก้ไข)

รอบอาการที่เจอสาเหตุจริงวิธีแก้สถานะ
1 โหลดรายชื่อไม่สำเร็จ: "Failed to send a request to the Edge Function" ฟังก์ชัน admin-user-mgmt มีโค้ดอยู่ในเครื่องแล้ว แต่ไม่เคย deploy ขึ้น Supabase จริง Deploy ฟังก์ชันขึ้นระบบ ✓ แก้แล้ว
2 โหลดได้ถึงฟังก์ชันแล้ว แต่ตอบกลับ 500 error โค้ดพยายาม join ตาราง staff กับ event_pins ผ่าน foreign key ที่ไม่มีอยู่จริงในฐานข้อมูล เขียนใหม่ให้ query แยก 2 ตาราง แล้ว join เองในโค้ด ✓ แก้แล้ว
3 รายชื่อขึ้นแล้ว แต่กด "สร้างผู้ใช้และ PIN" ไม่ได้ (400 Bad Request) หน้านี้อ่านค่า event ผิด key จาก context (ไม่เคยมีค่านี้จริง) → ส่ง event_id เป็นค่าว่างทุกครั้ง และหน้านี้ไม่เคยมี dropdown เลือกงานวิ่งมาตั้งแต่แรก เพิ่ม dropdown "เลือกงานวิ่ง" จริงที่หัวหน้า (ตามแบบหน้าอื่นในระบบ) แล้วผูกค่าให้ถูกต้อง ✓ แก้แล้ว
4 ผลข้างเคียงจากรอบ 3 ที่ตรวจพบระหว่าง verify (ก) แก้ไขผู้ใช้เดิมอาจโดนสลับ event ไปตาม dropdown โดยไม่ตั้งใจ  (ข) โหลดหน้าแรกมีจังหวะเห็นรายชื่อทุก event ปนกันก่อนกรองถูก  (ค) ถ้าโหลดรายชื่องานวิ่งพลาด หน้าจะค้างไม่มีข้อความแจ้ง ล็อก event เดิมไว้ตอนแก้ไข ไม่ให้ dropdown มายุ่ง / ไม่ยิง query จนกว่าจะเลือก event / เพิ่ม toast แจ้งเตือนเมื่อโหลดพลาด ✓ แก้แล้ว
