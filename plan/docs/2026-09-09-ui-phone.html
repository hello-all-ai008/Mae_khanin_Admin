🚨 แจ้งเตือนปัญหาสำคัญเร่งด่วนที่พบ (Urgent Known Issues)

ตรวจพบปัญหาในการทดสอบระบบ 2 จุดสำคัญ ซึ่งส่งผลกระทบต่อกระบวนการ Check-in หน้างานและการแสดงผลจอ Monitor รายละเอียดและสาเหตุเชิงลึกมีดังนี้:

BUG #1 1. Check-in แล้วหน้า Monitor ไม่ Realtime และเวลาไม่ตรงกัน

พฤติกรรมของปัญหา:

  • เมื่อทำการสแกน Check-in บนหน้า CheckIn.jsx ข้อมูลนักวิ่งบนหน้า Monitor.jsx ไม่แสดงผลทันทีแบบเรียลไทม์ (ดีเลย์หรือไม่เด้งขึ้นมาเลย)
  • เวลาที่ปรากฏในกล่องสถานะ "Check in" บนหน้ามอนิเตอร์ ไม่ตรงกับเวลาที่เจ้าหน้าที่กดสแกนจริง เช่น แอดมินสแกนตอน 19:45:12 แต่หน้าจอกลับแสดงเวลา 06:00:00 หรือเวลาเริ่มต้นของงาน

การวิเคราะห์สาเหตุเชิงเทคนิค (Root Cause Analysis):

  • การตัดการเชื่อมต่อ WebSocket ซ้ำซ้อน (Subscription Loop): ใน Monitor.jsx ตัว useEffect ฟัง Channel supabase.channel('rohn_monitor_stream') ถูกผูกไว้กับ Dependency Array [castEvent, monitorId, getRunnerByBib] เมื่อมีข้อความ Broadcast เข้ามา castEvent จะเปลี่ยนค่า ทำให้ React ยกเลิก Subscription เดิมแล้วเชื่อมต่อใหม่ทุกครั้ง จึงเกิดการหลุดของ Realtime Connection
  • การดึงเวลาผิดตัวแปร (Fallback to Gun Start Time): ใน Monitor.jsx ตัวแปร effectiveTime มีการ Fallback ไปหยิบ displayData.gunStartTime หรือ runner.gun_start_time (ซึ่งเป็นเวลาปล่อยตัวตอนเช้า เช่น 06:00:00) แทนที่จะยึดเวลาเช็คอินจริง checkinTime (Timestamp ที่สแกนจริง)
  • ข้อจำกัด Cross-Origin Isolation: แอดมิน (พอร์ต 5173 หรือมือถือ) และ Runner Monitor (พอร์ต 5174 หรือจอทีวี) อยู่คนละโดเมน/พอร์ต ทำให้ BroadcastChannel ในเครื่องไม่ส่งถึงกัน จึงต้องพึ่งพา Supabase Realtime WebSocket 100%
แนวทางแก้ไข (Fix Plan): แยก Realtime Subscription ใน Monitor.jsx ออกเป็นอิสระไม่ให้ Re-subscribe ซ้ำซ้อน และปรับลำดับการแสดงผลเวลาให้ยึด displayData.checkinTime เป็นอันดับแรกเสมอ
BUG #2 2. หน้าแก้ไขเวลา ลบเวลาออกไปแล้ว แต่กลับมา Check-in ใหม่ไม่ได้

พฤติกรรมของปัญหา:

  • เมื่อเข้าไปที่หน้าจัดการเวลา (RunnerTimingModal หรือ RunnerProgressControl) แล้วลบเวลา Check-in ออก (เพื่อทดสอบหรือรีเซ็ตนักวิ่ง)
  • พอกลับมาสแกน BIB เดิมที่หน้า CheckIn.jsx ระบบขึ้นแจ้งเตือนว่า "Check in แล้ว : XX:XX:XX (ยึดเวลาแรก)" และไม่ยอมบันทึกการเช็คอินใหม่ให้

การวิเคราะห์สาเหตุเชิงเทคนิค (Root Cause Analysis):

  • ความไม่ตรงกันระหว่าง Database กับ In-Memory State: ฐานข้อมูลจริงใน Supabase เก็บเวลาเช็คอินในคอลัมน์ checked_in_at (TIMESTAMP) และสถานะ registration_status แต่ในหน่วยความจำของ RaceContext.jsx มีการแปลงเป็นตัวแปร r.checkin (Epoch Milliseconds)
  • การลบเวลาไม่ได้ล้าง State ใน RaceContext: เมื่อกดบันทึกใน RunnerTimingModal.jsx โค้ดส่งอัปเดตลง Supabase เป็น checked_in_at: null แต่ในแคชและหน่วยความจำของ RaceContext ตัวแปร r.checkin ยังคงค้างค่าเวลาเดิมอยู่
  • ฟังก์ชัน processScan ตรวจสอบ if (r.checkin): ฟังก์ชันตรวจจับว่าหาก r.checkin มีค่าอยู่ จะถือว่าเป็น สแกนซ้ำ (Rescan) ทันที ส่งผลให้ result.success = false และปฏิเสธการเช็คอินรอบใหม่
แนวทางแก้ไข (Fix Plan): ใน RunnerTimingModal ต้องอัปเดตให้ checkin: null พร้อมกับ checked_in_at: null และเรียก updateRunner() หรือ refreshRunners() ใน RaceContext เพื่อล้างแคชทันที

📱 2. สรุปผลการพัฒนาและปรับปรุงระบบในวันนี้ (2026-09-09)

1. Responsive Mobile Scanner Pages

แก้ไขปัญหาจอล้นแนวนอน (Horizontal Overflow) บนหน้าจอมือถือทุกขนาดอย่างสมบูรณ์แบบ

  • ครอบคลุม 3 หน้าสแกน: CheckIn.jsx, CheckPoint.jsx, FinishLine.jsx
  • ปรับแถบสรุปข้อมูลเป็น .stat-grid-3 ไม่ตกบรรทัด
  • ตารางสแกนล่าสุดสามารถเลื่อนแนวนอนเฉพาะตาราง ไม่ดันโครงสร้างหน้า

2. Dark LED Mobile Result Card

พัฒนาคอมโพเนนต์ MobileScanResultCard.jsx จำลองป้ายไฟ LED ความคมชัดสูง

  • BIB ขนาดใหญ่พิเศษ มองเห็นชัดเจนกลางแจ้ง
  • แสดง Category Tag สีตามระยะทางจริง (10KM, 5KM)
  • แสดงผลสถานะผ่าน (เขียว), สแกนซ้ำ (ส้ม), ไม่พบ (แดง) ชัดเจน

3. Streamlined & Clutter-Free UI

จัดระเบียบพื้นที่หน้าจอมือถือให้คลีนและใช้งานง่ายที่สุด

  • ย้ายการตั้งค่าสถานี/จอ Monitor/แคช ไปไว้ใน StationSetupModal
  • ประวัติการสแกนด้านล่างสามารถกดพับเก็บ (Collapsible) ได้
  • เพิ่มพื้นที่การทำงานให้กับช่องสแกนกล้องและผลลัพธ์

4. Monitor Page Updates (Rohn-Runner)

ปรับปรุงหน้าจอ Monitor สำหรับแสดงผลบนจอทีวีและโปรเจกเตอร์

  • เปลี่ยนป้ายจาก "START DATE" เป็น "Check in" ตามที่ระบุ
  • รองรับการลากปรับขนาดสัดส่วนซ้าย-ขวา (Resizable Split Divider)
  • เชื่อมต่อ Supabase Realtime Broadcast รองรับการยิงข้อมูลข้ามอุปกรณ์

📋 4. รายการสิ่งที่ยังขาด & แผนการดำเนินงานถัดไป (Pending Gaps & Next Steps)

รายการงาน (Task) ความสำคัญ แนวทางการดำเนินการแก้ไข
1. ปรับปรุง Realtime Connection บน Monitor เร่งด่วน แยก Subscription ของ rohn_monitor_stream ไม่ให้ทำลายและเชื่อมต่อใหม่เมื่อ State เปลี่ยน เพื่อให้ข้อความเด้งขึ้นทันที 100%
2. แก้ไขการแสดงเวลา Check-in บน Monitor เร่งด่วน เปลี่ยน Logic การคำนวณเวลาให้ยึดเวลาที่สแกนเช็คอินจริง (Check-in Time) ไม่นำเวลาปล่อยตัว (Gun Start Time) มาแสดงทับ
3. แก้ไขการลบเวลาแล้วเช็คอินใหม่ไม่ได้ เร่งด่วน ใน RunnerTimingModal และ RaceContext ต้องล้างทั้ง checked_in_at = null และ checkin = null เพื่อให้สแกนใหม่ได้ทันที
4. ทดสอบ End-to-End บนอุปกรณ์จริง สำคัญ ทดสอบใช้สมาร์ทโฟนจริงสแกนที่หน้า /checkin แล้วตรวจดูการเด้งขึ้นของข้อมูลและเวลาบนจอทีวี /monitor/1 พร้อมกัน
5. ทดสอบระบบแคชออฟไลน์ (Offline Mode) ปกติ ตัดสัญญาณอินเทอร์เน็ตบนมือถือ แล้วทดสอบสแกนต่อเนื่องเพื่อยืนยันว่าคิวออฟไลน์ซิงค์ขึ้น Cloud ได้อย่างถูกต้องเมื่อเน็ตกลับมา
