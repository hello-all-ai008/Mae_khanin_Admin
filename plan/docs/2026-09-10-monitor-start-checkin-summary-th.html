สรุปงาน: Monitor Start vs Check In Display Fix

วันที่ 10 กันยายน 2569  |  โปรเจกต์ ROHN Runner & ROHN Admin  |  Completed

🔴 ปัญหาที่พบ (Problem Identified)

หน้า Monitor (/monitor/:id) แสดงข้อความ "Check in (scheduled)" สำหรับทุกการสแกน ซึ่งไม่ถูกต้อง ควรต้องแยกออกเป็น 2 กรณีคือ:

  • สแกนจาก หน้า Scanner หรือ Manual BIB บน Monitor → แสดง "START" ตามด้วย เวลาปล่อยตัว (gun_start_time) ตามระยะทางของนักวิ่งคนนั้น
  • เช็คอินจาก Admin CheckIn (Rohn-Admin) → แสดง "CHECK IN" ตามด้วย เวลาที่เช็คอินจริงจากฐานข้อมูล

⚠️ สาเหตุของปัญหา (Root Cause)

  • ฟังก์ชัน resolveCheckinTime() เดิมไม่แยกประเภทของ source ที่ส่งมาจาก broadcast
  • View public_results ของ Supabase บางแถวมี gun_start_time = null ทำให้การ fallback ไม่ทำงาน
  • ไม่มีการตรวจสอบ field source ในข้อมูล broadcast ('rohn_runner_scanner' vs 'rohn_admin_checkin')

✅ สิ่งที่แก้ไข (Changes Made)

Rohn-Runner: RunnerContext.jsx

เพิ่ม fallback ใน checkInRunner() — ถ้า runner.gun_start_time ว่าง ให้หา runner อื่นที่ระยะทางเดียวกันที่มีข้อมูลนี้:

runners.find(r => distance เดียวกัน && r.gun_start_time)

Rohn-Runner: Monitor.jsx

  • ลบ resolveCheckinTime() — แทนด้วย logic ที่ตรวจ source
  • เพิ่ม helper getGunStartTimeByDistance(runner, runnersList) — resolve gun_start_time โดยใช้ระยะทางและ cat_name
  • อัปเดต applyEvent() ให้แยก:
    • rohn_admin_checkin → ดึง checkinTime จาก broadcast หรือ runner.checked_in_at
    • rohn_runner_scanner → ใช้ gunStartTime จาก getGunStartTimeByDistance()
  • อัปเดต render: statusLabel = "Check in" หรือ "Start" ตาม source

Rohn-Admin: CheckIn.jsx

แก้ URL ของ openMonitorWindow() ให้ตรวจ port แบบ dynamic แทนที่ hardcode:

const runnerPort = window.location.port === '5173' ? '5174' : '5173';

⚠️ สิ่งที่ยังค้างอยู่ (Known Issues)

  1. Race condition ของ checked_in_at: ถ้า DB ยังไม่ commit ข้อมูล ณ เวลาที่ broadcast ส่งออก อาจแสดงเวลาปัจจุบันแทนแทนเวลาเช็คอินจริง (edge case, ยอมรับได้สำหรับงาน live)
  2. public_results view: ต้องตรวจสอบว่า view นี้มี column checked_in_at และ checkin จริงๆ หรือไม่ ด้วย Supabase SQL query
  3. Port auto-detection: การตรวจ port แบบ dynamic ใช้ได้แค่ใน local dev — production ใช้ vercel domain แยกกัน

🚀 ขั้นตอนถัดไป (Next Steps)

  • ตรวจสอบ view public_results ว่ามี checked_in_at และ checkin ครบหรือเปล่า
  • พิจารณาเพิ่ม column gun_start_time ใน CATEGORIES table (ตาม DatabaseFlow.jsx) เพื่อให้ resolve ได้ง่ายกว่า
  • เพิ่ม end-to-end test สำหรับ flow Admin CheckIn → Monitor broadcast
