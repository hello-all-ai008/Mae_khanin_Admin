Database Flow & Schema (TrailTime)

2. Table Structures

2.1 RUNNERS (ข้อมูลนักวิ่ง)

Field NameData TypeDescription
idUUID (PK)รหัสอ้างอิงนักวิ่งในระบบ (ใช้เป็น FK แทน bib เพราะ bib อาจว่างได้)
bibVARCHAR (nullable, UNIQUE)หมายเลขบิบ (เช่น "1001") — อาจว่างได้ถ้ายังไม่ออกบิบให้
nameVARCHAR (nullable)ชื่อ-นามสกุล — อาจว่างได้ถ้าเป็นบิบที่พิมพ์/จองไว้ล่วงหน้าแต่ยังไม่ระบุตัวคนจนกว่าจะเช็คอิน
genderVARCHARเพศ (M/F)
age_groupVARCHARรุ่นอายุ
category_idVARCHAR (FK)รหัสระยะทาง (อ้างอิง CATEGORIES)
rfid_tagVARCHAR (nullable, UNIQUE)รหัสชิป RFID — ไม่บังคับกรอกล่วงหน้า มักจะถูก map ตอนเช็คอินหน้างาน
registration_statusENUMPRE_REGISTERED (จองบิบไว้ล่วงหน้า) | CHECKED_IN (มารับบิบ/ชิปแล้ว)
checked_in_atTIMESTAMP (nullable)เวลาที่มาเช็คอินรับบิบ/ชิปที่หน้างาน
checked_in_byVARCHAR (nullable)เจ้าหน้าที่/เคาน์เตอร์ที่ทำการเช็คอินให้
updated_atTIMESTAMPเวลาที่แก้ไขข้อมูลล่าสุด

nameVARCHARชื่อเต็มของระยะ
distance_kmFLOATระยะทาง
unitVARCHARหน่วยวัดระยะทาง (เช่น "km")

2.3 LOCATIONS (สถานที่จริง)

Field NameData TypeDescription

nameVARCHARชื่อสถานที่
latitudeFLOATละติจูด
longitudeFLOATลองจิจูด
urlVARCHARลิงก์แผนที่ (เช่น Google Maps)

2.4 STATIONS (จุดสแกน)

Field NameData TypeDescription
idVARCHAR (PK)รหัสจุด (START, A1, FINISH)
nameVARCHARชื่อจุดสแกน
typeENUMประเภท (START, CHECKPOINT, FINISH)
sequence_orderINTลำดับของจุด (global, ไม่ได้แยกตาม category)

2.5 CHECKPOINT (เส้นทางของแต่ละระยะ)

ตารางกลางที่กำหนดว่าระยะ (category) ไหนต้องผ่านจุด (station) ใดบ้าง ตามลำดับอะไร และมี cutoff time เมื่อไหร่ — เพราะแต่ละระยะมักไม่ผ่านจุดสแกนชุดเดียวกัน

Field NameData TypeDescription
idUUID (PK)รหัสรายการ
category_idVARCHAR (FK)ระยะการแข่งขัน (อ้างอิง CATEGORIES)
station_idVARCHAR (FK)จุดสแกน (อ้างอิง STATIONS)
sequence_orderINTลำดับของจุดนี้ สำหรับระยะนี้โดยเฉพาะ
cutoff_timeTIMESTAMP (nullable)เวลาตัดตัว ณ จุดนี้ สำหรับระยะนี้
created_atTIMESTAMPเวลาที่สร้างรายการนี้
updated_atTIMESTAMPเวลาที่แก้ไข (เช่น เลื่อน cutoff_time)

2.6 SCAN_LOGS (ประวัติการสแกน Check Point)

Field NameData TypeDescription
idUUID (PK)รหัสรายการ
runner_idUUID (FK)อ้างอิงนักวิ่ง (RUNNERS.id)
station_idVARCHAR (FK)จุดที่สแกน (อ้างอิง STATIONS)
location_idVARCHAR (FK)สถานที่จริงที่สแกน
scan_timeTIMESTAMPเวลาที่สแกน
is_validBOOLEANเช็คว่าถูกต้อง (ไม่ได้สแกนซ้ำ, ผ่านจุดตาม sequence ของ CHECKPOINT ครบ)
scanned_byVARCHAR (nullable)ผู้ทำการสแกน เช่น ชื่อ/รหัสเจ้าหน้าที่ กรณีใช้เครื่องสแกนบาร์โค้ดแทนการแตะ RFID อัตโนมัติ
noteVARCHARหมายเหตุการสแกนผิดพลาด
created_atTIMESTAMPเวลาที่ record ถูกสร้างในระบบ
updated_atTIMESTAMPเวลาที่แก้ไขล่าสุด (เช่น staff แก้ scan_time/is_valid ย้อนหลัง)

3. Data Flow

  1. Pre-race (จองบิบ): สร้างบิบใน RUNNERS ผูกกับ category_id ล่วงหน้าได้เลยแม้ยังไม่รู้ว่าใครจะได้ (name/rfid_tag เป็น null, registration_status = PRE_REGISTERED) พร้อมกำหนด LOCATIONS และเส้นทางแต่ละระยะใน CHECKPOINT
  2. เช็คอินหน้างาน: นักวิ่งมารับบิบ -> กรอก/ยืนยัน name และ map rfid_tag เข้ากับบิบที่เคาน์เตอร์ -> อัปเดต registration_status เป็น CHECKED_IN พร้อม checked_in_at
  3. Start: สแกนบิบที่จุดปล่อยตัว -> บันทึกลง SCAN_LOGS พร้อมระบุ location_id
  4. Check Point: สแกนระหว่างทาง -> บันทึกลง SCAN_LOGS (ระบบเช็คกับ CHECKPOINT ว่าจุดนี้ถูกต้องตามลำดับของ category นั้น และผ่าน Start มาแล้วหรือยัง)
  5. Finish: สแกนเข้าเส้นชัย -> บันทึกเวลาลง SCAN_LOGS -> คำนวณเวลาเพื่อแสดงผล
